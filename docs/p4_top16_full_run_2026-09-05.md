## Four Physical Cards

Only physical cards 4-7 are used. On this host they expose logical devices 8-15.
TP=4 and SP=4 remain unchanged; the number of rollout/drafter replicas falls
from four to two. The launcher avoids global Ray stop commands.

| Budget | P2_02 per replica | P4 per replica | Global budget |
| --- | --- | --- | --- |
| Drafter optimizer batch | 4 | 8 | 16 |
| Maximum collected samples | 20 | 40 | 80 |
| Maximum collected feature tokens | 16384 | 32768 | 65536 |
| Internal fixed-eval cohort | 4 | 8 | 16 |

These settings preserve global data and optimizer budgets, not identical
floating-point updates or wall-clock time. Collection sampling, eligible trace
positions, and length limits can make actual collection smaller than its cap.

The drafter keeps four-way within-replica FSDP sharding; its replica dimension
changes from four to two. The loss reduction computes a global token mean and
compensates for FSDP gradient averaging, so the worker-count change does not
require scaling the learning rate. The doubled local batch increases activation
memory. Sampling groups and reduction order change, so identical numeric
trajectories are not expected. Raw throughput is not directly comparable with
the old sixteen-worker run.

## Fixed Evaluation Trajectories

Optional settings (disabled by default in the shared configuration):

```yaml
actor_rollout_ref.rollout.drafter.training:
  fixed_eval_export_steps: [60, 80, 100]
  fixed_eval_export_samples: 128
  fixed_eval_export_seed: 17
  fixed_eval_export_dir: null
```

Each requested rollout exports up to 128 uncollected responses. Selection is
deterministic and round-robin across distinct prompts, without filtering by
reward or acceptance. With 64 prompts per rollout, 128 responses do not mean
128 distinct problems.

The export contains full unpadded prompt/response token IDs, response loss masks,
available proposal traces (including top-16 verification data), and a manifest
with a content hash and the matching actor checkpoint. Hidden states are not
cached for future reuse; recompute them with the recorded actor snapshot.

The hook runs before the current actor update. Therefore rollout steps 60, 80,
and 100 require actor snapshots 59, 79, and 99, respectively. The existing
offset-9 schedule already saves those snapshots. The launcher protects these
three actor checkpoints, disables the upstream unconditional actor-pruning
limit, and leaves other pruning to the existing retention watcher.

Files are stored below:

```text
outputs/drafter_analysis/dspark_online_101step__p4/<wandb_run_id>/
  k3_logprobs/
  fixed_eval_samples/
    step_60/{manifest.json,samples.jsonl.gz}
    step_80/{manifest.json,samples.jsonl.gz}
    step_100/{manifest.json,samples.jsonl.gz}
```

Exported responses are excluded from that rollout's drafter collection, but are
still part of actor PPO and the DAPO training stream. This is a fixed-trajectory
evaluation corpus, not an independent held-out benchmark. It is separate from
the small internal fixed-eval cohort and does not select between the two best
drafter checkpoints automatically.

## P4_01: First-Rejection Weighting (2026-09-06)

Use the existing entrypoint with environment variables and Hydra overrides;
do not create a separate launch script for each experiment.

The new optional training settings default to 1.0, preserving previous behavior:

- `dspark_rejected_first_weight_multiplier` (environment:
  `DSPARK_REJECTED_FIRST_WEIGHT_MULTIPLIER`).
- `dspark_rejected_suffix_weight_multiplier` (environment:
  `DSPARK_REJECTED_SUFFIX_WEIGHT_MULTIPLIER`).

Both require trace-aligned anchors when non-default, accept finite non-negative
values, and apply to either K3 or top-k rejected loss. They do not change the
response stream, accepted proposals, teacher probabilities, or attention masks.
The first rejected token is identified by `position == accepted_count`, not by
absolute block position zero. Existing position decay and joint weighted-token
normalization remain active. For P4_01 the rejected weight before joint
normalization is:

```text
first rejection at block position j: 0.5 * 0.8**j * 2.0
positions after that rejection:      0.5 * 0.8**j * 0.4
```

P4_01 keeps the P4 cold-start models, DAPO, full attention, response/rejected
student top-16, LR 1e-5, two four-device replicas on logical devices 8-15,
global rollout batch 64 x 5, and drafter batch 8 per replica. Differences:

| Setting | P4 | P4_01 |
| --- | --- | --- |
| First rejected-token multiplier | 1.0 | 2.0 |
| Subsequent rejected-branch multiplier | 1.0 | 0.4 |
| Maximum collected responses per replica | 40 | 64 |
| Feature-token cap per replica | 32768 | 32832 |
| Drafter optimizer steps every 5 actor steps | 5 | 8 |
| Extra fixed export steps | 60, 80, 100 | Disabled |
| Actor retention | Additional evaluation snapshots | Latest rolling checkpoint only |

32832 covers 64 crops of 512 training rows plus one alignment row. Collection
targets up to 128 response trajectories globally, not 128 distinct questions.
The unchanged internal holdout reserves eight responses per replica in the
first collection cycle, leaving at most 112 distinct training responses in that
cycle. Later cycles can use all 128 without within-cycle reuse, subject to
sample eligibility. There are 20 scheduled drafter cycles (160 optimizer steps)
over 101 actor steps. Dual best drafter retention, K3 dumps, save frequency 10,
and save offset 9 remain enabled. Existing P4 artifacts are not modified.

## P4_02: Student/Teacher Top-16 Union (2026-09-07)

`DSPARK_TOPK_SUPPORT=union` selects the optional
`actor_rollout_ref.rollout.drafter.training.dspark_topk_support=union` mode.
The default remains `student`, preserving P4 and P4_01. The objective remains
reverse KL, with both distributions normalized on the selected support:

```text
S = unique(student_top16 + teacher_top16)
loss = sum(q_S * (log(q_S) - log(p_S)))
```

Response support is selected from the current training student and detached
teacher distributions. Rejected support combines the rollout student's
post-Markov top-16 with the actor's top-16 at the actual proposed verification
prefix. It remains fixed within each drafter training cycle; current training
student probabilities are evaluated on that recorded support. Teacher IDs are
not taken from a different ground-truth branch. Actor sampling and verification
rules are unchanged; teacher top-k capture adds work to the verification path.

Trace buffers contain 32 slots (student 16 followed by teacher 16). Their
overlaps are masked before subset softmax, reverse KL, and probability-mass
diagnostics, so the actual unique support contains 16-32 tokens. Overlapping
tokens are never counted twice. Training rejects student-only width-16 traces
in union mode instead of silently falling back. New metrics are
`drafter/train/dspark_topk_union_enabled` and the response/rejected
`topk_support_size` averages; existing teacher/student mass metrics now measure
the union. Union and student-only loss values are not directly comparable.

P4_02 uses the original P4 training recipe, not P4_01: official cold start,
full attention, both top-k streams, 101 actor steps, 32 anchors per crop,
512-row training crops, per-replica collection cap 40 and token cap 32768,
per-replica optimizer batch 8, five optimizer updates every five actor steps,
LR 1e-5, response/rejected weights 1/0.5, position decay 0.8, and both
first/suffix multipliers 1.0. Physical cards 4-7 only (logical devices 8-15).
Dual best drafter retention and K3 dumps remain enabled. As requested in the
previous experiment, extra evaluation exports/actor retention are disabled;
only the latest rolling actor checkpoint is retained (save frequency 10,
offset 9). Existing P4 evaluation artifacts remain untouched.

## P4_03: First-Rejection Correct-Token CE (2026-09-08)

This run returns to P4's student-only top-16 response/rejected objectives and
full attention. It adds an independent optional auxiliary loss:

```text
L = L_P4 + 0.2 * mean_over_first_rejections[-log Q(correct_replacement)]
```

Configuration: `dspark_first_rejection_ce_alpha`, exposed by the existing
entrypoint as `DSPARK_FIRST_REJECTION_CE_ALPHA`. Its default is zero. Nonzero
values require trace-aligned anchors and exact full-vocabulary CE (full or
chunked). The user selected 0.2 after discussing the initial 0.1 suggestion.

The mask is `draft_position == accepted_count < draft_count` on valid response
labels. It trains the actual response replacement, not the recorded wrong
proposal, accepted positions, or suffix positions. It applies no K3/log-Q
clamp, stream multiplier, or absolute-position decay. Its numerator and first
rejection count are reduced separately across the same SP/DP groups as the
base objective, including ranks with zero local first rejections; FSDP gradient
averaging is compensated. The base objective and its denominator are preserved.
The reported training and internal fixed-cohort total losses include this term.

| Setting | P4_03 |
| --- | --- |
| Initial models | Official Qwen3-8B / DSpark block-7 cold start |
| Dataset / rollout batch | DAPO / 64 prompts x 5 responses |
| Attention / training crop | Original full / 512 training rows |
| Response / rejected support | Student top-16, no teacher union |
| Base stream weights / rejected decay | 1 / 0.5 / 0.8 |
| Rejected first / suffix multipliers | 1 / 1 |
| First-rejection CE alpha | 0.2 |
| Whole-response CE / FKL alpha | 0 / 0 |
| Update interval / optimizer steps | Every 5 actor steps / 6 |
| Collection per replica / globally | 48 / 96 responses per cycle |
| Collection token cap per replica | 32768, sufficient for 48 x 513 |
| Optimizer batch per replica / globally | 8 / 16 |
| LR / schedule | 1e-5 / constant |
| Actor steps / scheduled drafter optimizer steps | 101 / 120 |
| Save schedule | Frequency 10, offset 9, dual best drafter retained |
| K3 dump | Enabled |
| Additional fixed exports / protected actors | Disabled; latest rolling actor only |
| Devices | Physical cards 4-7, logical devices 8-15 |

The first collection reserves eight internal evaluation responses per replica,
leaving 80 unique global training responses for 96 draws in that cycle. Later
cycles can cover 96 unique responses without within-cycle reuse. These counts
refer to responses, not distinct DAPO questions. The existing step-5 internal
fixed cohort is retained for continuity; this experiment does not implement the
separate proposed evaluation redesign.

New W&B training metrics (prefix `drafter/train/dspark_`):
`first_rejection_ce_enabled`, `first_rejection_ce_alpha`,
`first_rejection_ce_loss`, `first_rejection_ce_q_prob`,
`first_rejection_ce_contribution`, and `first_rejection_ce_token_count`.
The contribution metric is alpha times pooled CE over the cycle's first
rejection observations. Token count follows the existing SP-reduced diagnostic
convention and must not be interpreted as an independent sample count.
The K3 dump still records raw token probabilities for later pair analysis.
